# Архитектура

Пайплайн — цепочка стадий, обменивающихся файлами (JSON, `MatchData` из `schemas.py`).
Каждая стадия запускается отдельно и проверяется отдельно.

```
видео ─► ingest ─► vision ─► events ─► analytics ─► report
         прокси    детекция  владение   метрики     план улучшений
         клипы     трекинг   потери     ошибки      + клипы
                   команды
                   номера
                   поле (м)
```

## Стадии

| Стадия | Вход | Выход | Модуль |
| --- | --- | --- | --- |
| ingest | ссылка/файл | прокси 720p 25 fps, куски по 5 мин | `ingest/prepare.py` |
| детекция и трекинг | кадры | треки игроков и мяча в пикселях | `vision/detect.py`, `track.py` |
| команды | треки + кадры | `team` у каждого трека | `vision/team_split.py` |
| номера | треки + кадры | `number`, `number_conf` (голосование) | `vision/jersey.py` |
| поле | треки + ключевые точки | координаты в метрах | `vision/pitch.py` |
| события | треки в метрах | потери, отборы, владение | `events/possession.py` |
| метрики и ошибки | события + треки | `Finding` с клипом | `analytics/` |
| план | `Finding` | markdown + клипы | `report/plan.py` |

## Принципы

1. **Проверяемость.** Каждая находка имеет момент времени и клип; план без ссылок на эпизоды невозможен.
2. **Честность данных.** Камера видит часть поля: метрики — оценки. Неуверенный номер остаётся `None`.
3. **Человек в контуре.** Номера, события и ошибки можно поправить вручную до отчёта (интерфейс — этап 8).
4. **Тяжёлое отдельно.** Нейросети (GPU) подключаются лениво; ядро (метрики, правила, отчёт) работает на CPU и тестируется без видео.
5. **LLM только для формулировок.** Модель получает JSON находок и не имеет права добавлять факты (`report/plan.py: build_llm_prompt`).

## Где считать

GitHub Actions подходит для скачивания, проверок кода и лёгких стадий. Детекцию и распознавание номеров
запускать на GPU: своя машина (self-hosted runner), Colab/Kaggle или арендованная GPU на время матча.
